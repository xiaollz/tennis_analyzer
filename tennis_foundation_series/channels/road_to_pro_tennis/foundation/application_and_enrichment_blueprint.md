# Road to Pro Tennis：知识库应用与内容补齐蓝图

当前交付提供了完整的频道索引和标题级训练主题骨架。它适合作为**内容检索、课程资源导航、后续转录任务分配和 VLM 观察模板**的基础；但在获得逐视频字幕、人工笔记或可审计音画分析前，不应声称已掌握视频内的具体教学主张。

## 1. 三层知识模型

| 层级 | 当前状态 | 数据对象 | 可安全执行的功能 |
|---|---|---|---|
| L0 视频资源层 | 已完成 | 151条视频 ID、URL、时长、类型、标题、范围 | 搜索、筛选、播放列表和选题统计 |
| L1 主题地图层 | 已完成 | 141条训练相关视频的技术、移动、战术、训练和心理主题标签 | 课程导航、内容缺口分析、VLM任务路由 |
| L2 证据化教学层 | 待补齐 | 时间码、主张、条件、机制、动作线索、练习与反例 | 教练Agent、个性化教学、可引用问答与因果图谱 |

系统界面必须在每个资源卡片展示 `evidence_status`。当前绝大多数教学资源为 `metadata_title_only`；这意味着用户可以看到“该视频与什么训练主题有关”，但不能看到未经验证的“视频主张”。

## 2. 内容补齐管线

```text
视频索引 → 选择主题批次 → 取得字幕/人工观看笔记/合规音画分析
      → 原子主张（含时间码与证据类型） → 条件、机制、动作和练习单元
      → 人工教练审阅 → 课程、Agent与VLM索引
```

| 批次 | 主题 | 标题级候选数 | 内容补齐后的首要产物 |
|---|---|---:|---|
| P1 | 发球 | 39 | 站位、延迟、手腕、速度、时序与练习单元 |
| P2 | 正手 | 28 | inside-in/inside-out、开放式、力量、膝屈与球路单元 |
| P3 | 反手、网前与特定球型 | 44 | 反手、截击、过顶、接发、切削、放短和挑高单元 |
| P4 | 步法与战术 | 27 | 分腿垫步、第一步、站位、风险和比赛决策单元 |
| P5 | 学习、心理与竞技发展 | 93 | 训练设计、反馈、信心、学习环境与发展路径单元 |

候选数可以跨主题重复，因此不应累加为视频总数。批次优先级可依据后续产品目标调整：若先做 VLM 技术复盘，应先做 P1–P4；若先做学习平台，应在 P5 中优先补齐练习设计和反馈内容。

## 3. 训练知识单元的最小合格标准

每个被升级为 `video_explicit` 的视频单元必须至少包含以下字段。

| 字段 | 合格标准 | 示例（字段类型，不是当前内容结论） |
|---|---|---|
| 训练问题 | 明确描述球员要解决的表现问题 | “某类发球时机不稳定” |
| 条件 | 水平、球况、站位、目标或限制 | “初中级、平底式、追求入界” |
| 主张与时间码 | 可回到原视频的语言或演示 | `00:45–01:12` 的明确说明 |
| 机制 | 解释主张在身体/球拍/决策层的理由 | 必须区分视频明示与分析推断 |
| 线索 | 可执行的动作或注意力线索 | 不得脱离条件单独呈现 |
| 练习与成功标准 | 一个变量、一种检验方式 | “十球中的目标区命中率” |
| 风险/边界 | 不适用情境、疼痛或需转介标记 | 医疗问题须由专业人员审阅 |
| VLM 观察项 | 可见事实、推荐机位与误判风险 | “脚步时序”；不推断内部力矩 |

## 4. 应用路由

| 应用 | L0/L1可用能力 | L2完成后可用能力 | 护栏 |
|---|---|---|---|
| 知识管理 | 主题导航、资源筛选、重分析队列 | 证据问答、冲突主张和条件检索 | 禁止将标题改写成教学结论 |
| 教学系统 | 依据技术族组织观看和练习资源 | 分层课程、前置能力、进阶/回退 | 不依据观看次数判断掌握 |
| 网球Agent | 识别问题所属技术/战术域，追问条件 | 给出带证据的单变量练习方案 | 必须显示证据状态和不确定性 |
| VLM | 路由到发球、正手、脚步等事件模板 | 事件观察、假设、补拍与教练复核 | 不诊断伤病或单镜头断言因果 |

## 5. 建议的短期数据治理规则

第一，所有原始视频条目保持不可变 ID 与 URL。第二，转录或分析结果采用追加式记录，不覆盖标题级源信息。第三，任何跨视频总结必须保存其支持的 `video_id` 列表、证据类型、适用条件和反例。第四，伤病、疼痛和药物相关内容不能自动进入训练建议，应标记为需要专业审阅。
