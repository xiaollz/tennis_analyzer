# 哪些 OBS 适合用关键点（Pose）量化（OBS-01…29）

> 性质：**只写清单，不写应用代码。** 不改树、不改规则、不跑模型。写于 2026-10-18。
> 依据：`pipeline/obs_catalog.json`（29 项）+ 仓库现有 Pose/KPI 流水线（`/workspace/tennis_analyzer`：`core/pose_estimator.py`、`analysis/kinematic_calculator.py`、`evaluation/event_detector.py`、`evaluation/kpi.py`、`evaluation/hsa_detector.py`；运行方式见 `.agent/skills/tennis-analyze-runner`）。
> 适合度三档：**适合**＝现有关键点能直接给出该量，主要风险是阈值与机位；**部分**＝只能给出相关量（代理量）或只能回答其中一部分；**不适合**＝关键点本身不含所需信息，需要球 / 拍 / 手指检测，或应继续由人工 / Gemini 看。

## 0. 现有流水线能力（决定了能量化什么）

| 能力 | 现状 |
|---|---|
| 关键点 | YOLO11m-pose，**COCO-17**：鼻、双眼、双耳、双肩、双肘、双腕、双髋、双膝、双踝；2D 像素坐标 + 置信度。**没有**脚跟 / 脚尖 / 手指 / 拍子 / 球。 |
| 已有量 | 肘角、膝角（含最小膝角）、肩线 / 髋线向量与角度、肩髋夹角、肩旋转（带符号）、脊柱相对竖直角、手腕相对髋的前向距离（及按躯干高 / 肩宽归一化）、肘在躯干后方距离、肘相对高度、腕低于肘距离、髋中心垂直位置与垂直加速度、前臂角（肘→腕）、角速度、转速峰值帧、髋 / 肩峰值时间差、手腕横向位移、wiper 扫角。 |
| 事件 | 击球帧：音频起音 + 手腕速度的混合检测（`HybridImpactDetector`）；挥拍阶段（准备起点 / 随挥终点）由手腕速度阈值回溯估计（`SwingPhaseEstimator`）。 |
| 视角 | 有自动 / 手动的 `side` / `back` 视角门控；不同视角下只有部分指标有效。 |
| 已有 HSA 检测 | 大臂相对躯干横线的夹角（2D 近似），5 类闭合失败模式。 |

### 通用局限（所有条目共用，下表不再重复）
1. **2D 投影**：深度方向（朝向镜头 / 远离镜头）的量不可靠；侧面机位看不到左右、背面机位看不到前后。
2. **没有拍、没有球**：凡是问「拍杆 / 拍头 / 拍面 / 球」的题，关键点只能给手腕位置，不能给拍的朝向。
3. **手腕关键点 ≈ 握拍手的位置**，不是腕关节角：没有手背 / 手指点，**腕屈伸 / 前臂 roll（旋前旋后）无法直接测**。
4. **帧率**：30 fps 下 0.1 s 只有 3 帧；触球前后的减速 / 先后顺序类题分辨率不够；教练视频常是慢动作 / 剪辑 / 变焦，节奏与像素速度不可比。
5. **遮挡与镜头**：持拍臂常被身体遮挡；教练视频有切镜头、特写、多人入画，需要先做「选对人 + 选对片段」。
6. **阈值需要标定**：本表只写「需要什么量」，所有数值阈值都要先在已标注片段上标定，不得凭经验写死。
7. 左右手需要用户 / 视频元数据指定（现有 CLI 有 `--left-handed`）。

## 1. 逐条清单

| OBS | 内容（简） | 层/机位 | 适合度 | 需要的关键点与估算量 | 局限 / 说明 |
|---|---|---|---|---|---|
| 01 | 触球时肘是否明显弯曲 | A / 任意 | **适合** | 持拍侧肩、肘、腕 → 触球帧肘角（`elbow_angle`）；触球帧来自混合击球检测 | 背面机位肘角被前缩，侧面最稳；触球帧误差 ±2–3 帧会影响读数 |
| 02 | 触球时手 / 大臂离躯干的距离 | B / 背面 | **适合（背面）** | 肘与腕到躯干中线的横向距离 ÷ 肩宽（`elbow_to_torso_distance` 一类） | 「贴肋 vs 有缝」阈值要标定；被身体遮挡时置信度低 |
| 03 | 触球点相对前髋的前后位置 | B / 侧面 | **部分** | 手腕 x 相对前髋 x 的归一化前向距离（`wrist_forward_normalised`）作代理 | 题目问的是「球 / 拍弦中心」，球无检测，只能用手代替，真实击球点可能差一个拍长；需知道前脚是哪只 |
| 04 | 引拍顶点是否停顿 ≥0.3 s | A / 任意 | **适合** | 手腕速度时间序列，找引拍最高 / 最后点附近低速平台的持续时间 | 慢动作视频需按倍率折算；30 fps 下 0.3 s≈9 帧，足够 |
| 05 | 是否有分腿垫步与小调整步 | A / 任意 | **部分** | 髋中心垂直位置 / 垂直加速度（`compute_vertical_acceleration`）、双踝垂直 / 水平位移，检测「小跳 + 落地」 | 需要球出手时刻作参照（发球机 / 对手出手）——流水线没有；全身必须入画 |
| 06 | 起挥时双脚相对来球方向的朝向 | A / 背面 | **部分** | 双踝连线相对底线 / 球网方向的夹角，近似开放 / 半开放 / 中立 / 关闭式站位 | **没有脚尖点**，只能得到「两脚的连线」而非「脚朝向」；来球方向无检测，需手工指定网的方向 |
| 07 | 非持拍手的三个子问题 | A / 背面 | **部分** | (a) 非持拍腕相对胸中线是否越过；(c) 非持拍腕相对肩 / 髋的高度（已落下 vs 随胸转）：均可由肩、腕、髋算 | (b)「离开拍的时刻」需要手拍接触检测，**不可**；(a)(c) 受遮挡影响 |
| 08 | 准备转体末端肩线 / 髋线转了多少 | B / 背面 | **部分** | 肩线 / 髋线在图像里的投影宽度 ÷ 躯干高（缩短越多转得越多），或 `shoulder_hip_angle` | 背面看可得「转动量」，但**前 / 后转向的符号有二义**，需用时序连续性或第三点（鼻）消歧 |
| 09 | 触球帧髋是否已转回正对目标 | B / 背面 | **部分** | 同 08，在触球帧取髋线投影宽度比 | 触球帧误差、符号二义同上 |
| 10 | 后脚：(a) 触球时是否脚跟离地；(b) 触球后脚的去向 | A / 背面 | **部分** | (b) 后踝轨迹分类：前摆 / 后踢 / 原地 → **适合**；(a) 需要脚跟点 | (a) **不适合**（无脚跟 / 脚尖），只能用「后踝比前踝抬高」做粗代理 |
| 11 | 起挥到触球手的路径 | B / 侧面 | **适合** | 起挥点（手腕速度起点）到触球帧的手腕 (x, y) 轨迹；分类：水平向前 / 先下再前上 / 先上抬 | 只在侧面可靠；画面倾斜需用地面线校正；起挥点定义要固定（手腕速度阈值） |
| 12 | 触球时 (a) 前臂角；(b) 拍杆角 | B / 侧面 | **部分** | (a) 前臂角（`forearm_angle`，肘→腕）适合；(b) 拍杆无关键点 | (b) **不适合**；(a) 前臂角与拍杆角不是一回事，不能互相代替 |
| 13 | (a) 触球时重心在前脚 / 后脚；(b) 触球后身体是否继续向网前移 | B / 侧面 | **部分** | (b) 髋中心前向位移速度 → **适合**；(a) 重心无法直接得到，只能用「髋中心 x 相对双踝 x」做代理 | (a) 地面压力无法测，仅姿态代理；需要球网方向 |
| 14 | 躯干前倾从准备完成到触球如何变化 | B / 侧面 | **适合** | `spine_angle_from_vertical`（髋中心→肩中心 vs 竖直）在「准备完成帧」与「触球帧」之差 | 需要知道朝哪个方向算前倾（脸朝向 / 球网方向）；镜头非垂直于击球线会压缩角度 |
| 15 | 随挥：(a) 拍收在哪；(b) 触球后手是否向目标延伸；(c) 末端肘是否在胸前 | A / 任意 | **部分** | (b) 触球后手腕前向位移 / 与躯干的距离曲线 → **适合**；(a) 用手腕终点相对非持拍肩作代理；(c) 肘相对胸中线 | (a) 拍无关键点，只是手的位置；(c) 背面 / 侧面都有二义；整体按子问题拆开用 |
| 16 | 每个球的结果（进 / 网 / 出 / 框） | A / 任意 | **不适合** | —— | 需要球检测 / 落点；这是结果不是姿态。继续靠字幕里球员口述或人工 |
| 17 | 引拍最深处拍头指向 | B / 背面 | **不适合** | —— | 无拍头点；前臂方向不能代表拍头（腕有角度） |
| 18 | 起挥时哪个部位先动（髋 / 躯干 / 手臂） | B / 背面 | **部分** | 髋线角速度、肩线角速度、手腕速度三条曲线的**起动时刻**；已有 `compute_angular_velocity`、峰值帧、髋肩峰值时间差 | 现有量是「峰值时间差」，题目问「起动先后」；起动点在噪声里难定，30 fps 下先后差常 ≤2–3 帧，**只适合粗分「手臂明显先动」与否** |
| 19 | 触球前躯干旋转是否减速 | B / 背面 | **部分** | 肩线角速度曲线在触球前 3–6 帧的斜率（`compute_rotation_speed`） | 分辨率不足（减速发生在 ~0.1 s 内）；击球帧误差直接污染结论；需 60 fps 以上才可靠 |
| 20 | 触球帧球相对身体的高度 | A / 任意 | **不适合** | —— | 需要球位置；可用髋 / 膝 / 肩作尺子，但球本身无检测 |
| 21 | 垫步落地相对对手触球的时刻 | A / 任意 | **不适合**（可降为部分） | 垫步：髋垂直位置可测；对手触球：只能靠音频起音（`AudioOnsetDetector`） | 自己的击球声会混入；无对手 / 球检测；要求带声音的整段回合；不建议优先 |
| 22 | 起挥时髋是铰链后坐还是前顶 | B / 侧面 | **部分** | 髋 x 相对踝 x、肩-髋-膝夹角、躯干前倾（与 14 联用） | 2D 难区分「髋铰链」与「屈膝下蹲」；只能给出「躯干前倾 + 髋后移」组合量 |
| 23 | 低球触球时膝弯曲程度 | B / 侧面 | **适合** | 前 / 后膝角，触球帧 `knee_angle`、`min_knee_angle` | 「低球」要先判定（OBS-20 无法测）→ 需人工标「低球」；膝被球拍 / 另一条腿遮挡时置信度低 |
| 24 | 触球前后腕是否快速屈伸 | B / 侧面 | **不适合** | —— | 无手背 / 手指点；前臂角变化多来自肘 / 肩，不是腕。继续由人工 / Gemini 看慢动作 |
| 25 | 起动时肩 / 髋谁先转 | B / 背面 | **部分** | 同 18（只用肩线 / 髋线两条曲线） | 同 18；与 OBS-18 语义重叠，量化时可共用同一套起动检测 |
| 26 | 球出拍的垂直出射角 | B / 侧面 | **不适合** | —— | 需要球轨迹（球检测 / 追踪），不在现有流水线内 |
| 27 | 触球时拍杆与前臂夹角是否保持 | B / 侧面 | **不适合** | —— | 同 17、24：无拍、无手 |
| 28 | 触球帧拍面倾角 | B / 侧面 | **不适合** | —— | 同上；拍面朝向在 2D 关键点里不存在 |
| 29 | 前挥入触球时脊柱是否侧弯、击球侧肩是否低于另一侧 | B / 背面 | **适合（背面）** | 肩线相对水平的倾角、髋中心→肩中心在冠状面（图像平面）里相对竖直的偏角 | 背面机位下是 2D 里最可靠的一类；镜头横滚 / 地面不平需校正；侧倾 vs 身体整体转动的投影变形要用髋线作参照 |

## 2. 汇总

| 适合度 | 条目 |
|---|---|
| **适合**（7） | OBS-01、02（背面）、04、11、14、23、29（背面） |
| **部分**（14） | OBS-03、05、06、07、08、09、10、12、13、15、18、19、22、25 |
| **不适合**（8） | OBS-16、17、20、21、24、26、27、28 |

> OBS-21 因「可降为部分」归入不适合栏，是保守处理。

### 机位需求归纳
- **侧面（S）**：OBS-03、11、12(a)、13、14、22、23、（01 最稳）。
- **背面（B）**：OBS-02、08、09、18、19、25、29（以及 07、10(b) 更易从背面看）。
- **任意**：OBS-04、05、15(b)。
- 一个镜头一次只能满足一类；同一个球要两个机位才能同时给 S 类与 B 类量，用户当前单机位视频只能二选一。

## 3. 建议的落地顺序（仅供决策，不含实现）

1. **先做 7 个「适合」**：11（手路径）、14（躯干前倾变化）、23（膝角）、29（侧弯，背面）、01（肘角）、04（停顿）、02（手-躯干距离，背面）。它们只依赖现有关键点和击球帧。
2. **再做「部分」里分辨率可接受的**：13(b)（触球后继续向前）、15(b)（随挥延伸）、10(b)（后脚去向）、08 / 09（转体量，需符号消歧）。
3. **先别碰**：18 / 19 / 25 这类毫秒级先后（需要 ≥60 fps，且击球帧要更准）；以及所有需要拍 / 球 / 手指的 OBS（16、17、20、24、26、27、28）——这些保持由人工 / Gemini 视频层判断，或将来引入球 / 拍检测后再议。
4. 任何量化结果都要先在人工标注片段上标定阈值、报告一致率；达不到之前，该 OBS 在树里仍按 `reliability: untested` 处理，不得用于判决。

## 4. 与诊断树的关系

- 本清单只回答「能不能自动量」，**不改变** `obs_catalog.json` 的 `layer` / `camera` 字段，也不改任何节点签名。
- 若以后给 OBS 增加 `pose_quantifiable` 字段（适合 / 部分 / 不适合），需要用户批准并走 `check_obs_binding` 的 O9 同步更新。
