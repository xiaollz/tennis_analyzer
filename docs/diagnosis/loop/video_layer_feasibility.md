# 视频层可行性（YouTube URL 直看 / 2026-10-18 夜）

> 范围：教练视频，不下载任何东西；用户自己的击球视频不在本轮。模型固定 `gemini-3.8-flash`（Micu，密钥只读环境变量）。
> 脚本：`pipeline/video_probe.py` + `pipeline/prompts/facts_video_v1.md`（中立；先描述后回答选择题；渲染稿先过 `check_neutrality.py`）。原始输出在 `/workspace/s1_work/video/`（仓库外）。

## 1. 结论（先看这里）

| 问题 | 结论 |
|---|---|
| 不下载、只给 YouTube URL，Gemini 能看吗？ | **能。** 必须用 camelCase：`fileData: {fileUri, mimeType:"video/mp4"}` + `videoMetadata: {startOffset, endOffset}`（snake_case `file_data` 被 Micu 中转层拒绝：HTTP 400）。输出里的时间戳是整段视频的绝对时间（mm:ss）。 |
| 成本 | 40 秒片段约 6–7k token（视频 ≈2.6–4k + 音频 ≈1–1.5k + 输出/思考），单次 40–110 秒墙钟。 |
| (a) 用来检验 / 更新卡片里的「可见动作」假设？ | **只能作弱旁证，不能当权威层。** 见第 3 节。 |
| (b) V5「静音片段盲测」能用 URL 方式做吗？ | **不能。** URL 方式无法去掉音轨，模型能逐字复述讲解语音（lwS7Xxqrrdw 06:25 实测）。静音盲测必须「下载片段 → `ffmpeg -an` → 本地 inline」，**需要用户批准下载**（PLAN_v2 §9.2：按片段批准）。本轮没有下载。 |

## 2. 实测

样本：`lwS7Xxqrrdw`（双手反拍示范，有卡，3 段）与 `NEpD7fIM7HI`（Federer 切削，有卡，2 段），每段 2 次独立运行（选项顺序按 seed 打乱），11 道从 `obs_catalog.json` 渲染的选择题，每题带 `unclear` 选项。共 10 次调用，约 69k token。

| 样本 | 两次运行答案完全一致 | 说明 |
|---|---|---|
| lwS7Xxqrrdw ×3 段 | 23 / 33（70%） | 不一致主要在 OBS-18（谁先动）、OBS-29（侧弯）、OBS-01 / 02 / 22 / 24 / 14（第 3 段，近距示范 + 反复切镜头） |
| NEpD7fIM7HI ×2 段 | 20 / 22（91%） | 不一致只在 OBS-11、OBS-25（其中一次选了 `unclear`） |

观察到的问题：
1. **多个题在不同片段给出同一个答案**（lwS7：OBS-08 恒为 clearly_sideways、OBS-11 恒为 down_then_forward_and_up、OBS-18 恒为 arm_first；NEpD：OBS-01、02、18、22、24、27、28、29 全部恒定）。恒定答案不能证明「看见了」，更像默认值；**一致性高 ≠ 有区分力**。
2. **音轨泄漏**：模型的描述里出现「手腕动作明显向上刷球」「身体直立」这类与讲解语音同义的话；无法区分是看出来的还是听出来的。对「可见动作假设」的检验因此被污染（教练说 stands up super tall，模型就描述直立）。
3. 教练视频常有切镜头、慢放、多人、画中画：描述里能看出模型会把示范者与学员混在一起，题目「针对被示范的那个动作」时容易串。
4. 与卡片的对照（仅旁证）：lwS7 的「纯手腕」段 OBS-24 两次都答 wrist_flexes_rapidly；「站直」段 OBS-22 答 extended_forward、OBS-23 答 nearly_straight，方向与卡片 C02 / C03 一致，但受上面第 2 点污染，**不能算独立验证**。

## 3. 能做什么 / 不能做什么

- **可以**（不下载）：
  - 用 URL + 时间偏移让模型对教练视频做「先描述」的粗检索（这一段画面里有什么、哪几秒是示范、机位是什么），用来为人工复核**定位片段**。
  - 作为 OBS 题目的可答性探针：题目是否会得到 `unclear`、是否在不同片段给出不同答案（本轮发现不少题恒定）。
- **不可以**：
  - 当作 V5 静音盲测（音轨泄漏）。
  - 当作「可见动作假设已被视频验证」的证据写进卡片 `video_layer`（`video_layer` 仍留空）。
  - 用来改树 / 改 `must_fix` / 放宽任何规则。
- **要做 V5 静音盲测需要的东西（留给用户批准）**：
  1. 批准下载**逐片段**（每个 holdout 用例约 20–40 秒；盲测用例清单需先从 holdout 字幕选定）；
  2. 本地 `ffmpeg -an` 去音轨后 inline（`facts_v2.md` 已按此设计）；每片段 3 次、选项顺序随机；
  3. 先对着 `check_neutrality.py` 过渲染稿；用例数 ≥10、期数 ≥5 才满足 G1（`config.json` 阈值不改）。
  估算：10 个用例 × 3 次 × 约 6k token ≈ 0.2M token，几分钟墙钟；主要成本是用户的下载批准与片段选取，不是模型。

## 4. 建议

1. V5 保持 FAIL（G1：0 个用例），如实记录；等用户批准逐片段下载后再做。
2. 视频层优先给「A 层、机位无关」的 OBS 做可答性验证（OBS-01、04、15 等），B 层（角度 / 先后）的题模型一致性与区分力都不够，先别作为判决依据。
3. 若要验证「卡片可见动作假设」，用无声片段（同上，需下载批准）比 URL 方式干净得多。
