# 教练诊断方法论：结构化分析顺序

> 来源：FTT、Feel Tennis (Tomaz)、Intuitive Tennis (Nikola)、TPA Tennis (Tom Allsopp)、Essential Tennis (Ian Westermann)、Top Tennis Training、Rick Macci 的免费 YouTube/博客内容 + 公开生物力学文献。

---

## 1. 共识诊断顺序（多教练交叉）

虽然每位教练用词不同，但当他们看一个学生的正手视频时，几乎都按 "结果 → 回溯 → 根因" 的顺序工作。综合后得到 5 步：

### Step 1 — 看 Contact（接触瞬间是"结果显示器"）
所有教练第一眼都落在接触点：
- 接触点是否在身体前方、侧方足够远？（FTT 把这个列为 prerequisite，所有其他改进都依赖它）
- 拍面是否中性、手腕是否处于 lag 位（Tomaz：腕背伸 >100°）
- 球路（深度/旋转/方向）作为"症状"读数

→ Contact 是 KPI 的"输出层"。如果 contact 没问题，多数情况下不必再深挖。

### Step 2 — 看 Timing / Rhythm（"准备早不早？")
Tomaz 的 parallel processing 原则：脚移动的同时上身就在转。
- 学生是不是先跑后准备？→ 这是业余球员第一大问题
- Unit Turn 在 split step 后多少帧内启动？
- 提前 0.2 秒到位（Tomaz 数字）才能让 wrist cock + 转髋有时间发生

→ Timing 不对，下面的 kinetic chain 一定散。

### Step 3 — 看 Kinetic Chain Sequence（"大块带小块"）
Ian Westermann / Rick Macci 的核心检查：髋 → 肩 → 臂 → 拍头是否按顺序释放。
- 是否 elbow 先走（"push"）→ 链条断在肩之前
- 是否肩髋分离不足（FTT：肩转得比髋多）
- 是否过度转髋（FTT：髋应在指向目标处停住）

→ 这一步把"症状（contact 差）"和"根因（准备问题）"连起来。

### Step 4 — 看 Preparation / Unit Turn（回溯到源头）
只有当前面 3 步暴露问题时，才往回看准备阶段：
- Unit Turn 完整度（肩转 90°+、非持拍手指向边线）
- 引拍路径（C-loop vs 直拉）
- 步法到位 + 重心在后腿
- 文献：40% 的击球错误起源于 preparation phase

### Step 5 — 看 Footwork / Setup（最底层）
Split step 时机、调整步、最后一步的方向。
- Tom Allsopp 强调：很多"上身问题"其实是脚没到位逼出来的代偿
- Macci："Feet are the engine"

→ 当 Step 1-4 找不到明显单点错误时，根因 90% 在脚。

**核心顺序公式**：`Contact (症状) → Rhythm → Chain → Preparation → Footwork (根因)`
即：**先看输出，再回溯输入**。这是 top-down 而不是 bottom-up。

## 2. 各教练独特视角

- **Tom Allsopp (TPA)**：先 mirror 学生的动作（自己复制一遍）再判断，强调"个性化诊断"而非通用清单。优先指出"哪些保留 / 哪些改 / 改的顺序"三件套。
- **Tomaz (Feel Tennis)**：强调 *parallel processing* 和 *提前 0.2s 到位*。第一眼看 timing 而不是几何形状。把"感觉"和"意图"作为输入，反推机械问题。
- **FTT (Fault Tolerant Forehand)**：Contact point 是 prerequisite；relaxation 作为贯穿所有步骤的复查项；power checklist 7 步（drive back leg → relax → breathe → turn shoulders → pull off-arm → don't over-rotate hips → re-verify relax）。
- **Nikola (Intuitive Tennis)**：用 swing path tracing + 与高水平球员叠加对比；区分 *intuitive zone vs non-intuitive zone*——只在非直觉区做机械干预。
- **Ian Westermann (Essential Tennis)**：第一警报是"elbow 先走"和"swing 太短太紧"；提醒不要只盯 follow-through，而要问"是什么让 follow-through 自然形成"。
- **Rick Macci**：feet → balance → 拍头加速路径，强调 racquet head speed 的源头在下盘。
- **Top Tennis Training (Konov)**：偏好 ATP-style 比对法，一帧一帧对比职业球员同阶段。

## 3. 因果链思维：表面 → 根因

教练几乎都用"WHY 链"反推。典型示例：

| 表面症状 | 中间层 | 根因 |
|---|---|---|
| 球下网 | 接触点偏后 | Unit Turn 启动晚 → 准备迟 → split step 时机差 |
| 球软无力 | 用手臂打 | Kinetic chain 在肩处断 → 肩髋分离不足 → 准备时未转肩 |
| 球总出界右侧 | 拍面在接触时打开 | 手腕 lag 没建立 → 引拍 C-loop 缺失 → 引拍时手腕僵硬 |
| Follow-through 包不住头 | 加速在接触点而非延伸 | 非持拍手没拉走 → 胸没转开 → Unit Turn 不完整 |
| 总打到框 | 接触点离身体太近 | 最后一步方向错 → 步法读球晚 → split step 滞后 |

教练共同的"WHY 反问"：**"为什么会这样？" 至少问 3 次才停**。

## 4. 优先级原则（先修哪个）

1. **安全 > 一切**：受伤风险动作（手腕/肩硬撞）立即修
2. **接触点 > 一切技术**：FTT 明确说没有合理 contact，其他改进白搭
3. **大块 > 小块**：髋肩问题优先于手腕拍面（动力链原则）
4. **时机 > 几何**：动作形状对但时机错 → 比形状错更难修，但优先级更高
5. **根因 > 症状**：不修 follow-through，修让 follow-through 自然出现的东西
6. **保留正确部分**：Tom Allsopp / Nikola 都强调先告诉学生"哪些不要动"
7. **一次只改一个**：多个问题排队，不并行修

## 5. 视频评论结构模板（YouTube 学生评论视频通用结构）

```
[0:00] Intro - 介绍学生背景、级别、要解决的问题
[0:30] First impression - 全速播一遍学生原视频
[1:00] Slow-mo observation - 慢放 + 暂停在关键帧（接触/引拍顶点/follow-through）
[2:00] What's working - 先肯定 2-3 个正确点（保留项）
[3:00] Diagnosis - 指出 1-2 个核心问题，给出 WHY 链
[5:00] Pro comparison - 叠加职业球员同阶段帧
[6:00] The fix - 解释正确动作的"feel"和"intent"
[7:00] Drill - 给 1-2 个具体练习方法
[8:00] Recap - 强调"先修这一个，其他不要动"
```

注意：**几乎没有教练会一次给超过 2 个改动**。

## 6. 对我们系统的启示

我们的 VLM + 诊断引擎应当按以下管线重构：

### Pipeline 顺序（与教练共识对齐）

```
[VLM 观察阶段：只描述，不诊断]
  L1. Contact frame 观察（接触点位置/拍面/手腕）
  L2. Rhythm 观察（split → unit turn → 接触 的时序）
  L3. Chain 观察（髋肩臂拍的释放顺序与分离角）
  L4. Preparation 观察（unit turn 完整度、引拍路径）
  L5. Footwork 观察（split 时机、最后一步方向、重心）

[诊断引擎阶段：基于 KPI 阈值 + 因果规则]
  D1. 症状层：从 L1 读取 contact KPI 是否异常
  D2. 回溯层：若异常，按 L2 → L3 → L4 → L5 顺序找最早出现偏差的层
  D3. 根因锁定：返回"最早异常层"作为 root cause，其余视为代偿
  D4. 优先级排序：动力链上游 > 下游；时机 > 几何；安全 > 性能
  D5. 输出：1 个根因 + 1-2 个保留项 + 1 个具体 drill
```

### 关键设计点

- **VLM 不做因果推理**，只输出每一层的结构化观察（解决"套概念"问题，与 v4.0 架构一致）
- **诊断引擎用规则**实现"WHY 链"：症状层异常 → 检查上游层 → 找到第一个异常源
- **报告输出限制**：每次只暴露 1 个核心修复点，符合"一次改一个"原则
- **保留项必须显式输出**：教练共识——先告诉学生哪些不要动
- **Contact point 作为 gating KPI**：若 contact 良好，跳过深层诊断
- **Preparation 不是"前置子模块"，而是"回溯目标"**：默认管线从 contact 倒推，不要从 preparation 正推

### 与现有系统的差异

- 现有 VLM 看的是孤立挥拍 → 应扩展为 5 层观察
- 现有诊断可能并行报多个问题 → 应改为"找最早异常层 + 单点输出"
- KPI 评分应分层（Contact/Rhythm/Chain/Prep/Footwork），并按因果上游加权
