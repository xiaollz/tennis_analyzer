# VLM Prompt 与教练叙述风格审计

审计对象：`evaluation/vlm_analyzer.py:_FTT_SYSTEM_PROMPT`、`evaluation/coach_style.py:COACH_OUTPUT_PRINCIPLES`、`evaluation/diagnosis_engine.py:_generate_narrative`，以及一个真实样本 `storage/diagnoses/41ae13dd6128_c000/report.md`。

度量：FTT prompt 本体 10885 字符 / 319 行，COACH_OUTPUT 1453 字符。两者拼接后约 12.3K 字符，是单次 vision call 的全部 system context。

---

## 1. 当前 prompt 的问题清单

### 1.1 强制 10 层 Checklist（vlm_analyzer.py:406-422） —— 系统层硬伤

让 VLM "每一次诊断必须按以下 10 层顺序逐一审查，任何一层省略 = 不完整诊断"，但 VLM 的输出格式是 38 个 Q1-Q38 的固定问答（见 `result.json` 里的 `raw_answers`）。VLM 实际上是在回答固定 schema，根本无法"按 10 层顺序自由输出"。这段 17 行的 checklist 在生成 schema 阶段毫无作用，只是占用注意力。

它真正起作用的地方是间接污染了 `overall_assessment` 字段——让 VLM 觉得必须把 L1-L10 各塞一句话，于是产出"L1 击球点偏低、L3 步法迟缓、L5 脊柱垂直、L6 Unit Turn 26°、L7 肘角 71°"这种"层级清单"风格的总结，而不是教练的说话。

### 1.2 L1 击球点专门 block（vlm_analyzer.py:425-433） —— 与 schema 重复

`contact_point` 已经是 JSON 输出的固定字段（vlm_analyzer.py:691-697），4 个坐标加 verdict 已经在 schema 里强制存在。再单独写一段"极重要，单独说"是冗余 prompting，且和 L1 checklist 重复一次。这个 block 砍掉，schema 里的字段定义本身就是约束。

### 1.3 16 条核心原则（vlm_analyzer.py:496-516） —— 长篇内化版教材

第 4 条单条 332 字，第 9-16 条都是百字长论。这些内容来自 `docs/research/13_synthesis.md`，已经训练进了 VLM 的认知，但每次都丢回去当 prompt，相当于把教科书塞进 system message。

最关键的问题是**它们不影响输出格式，只影响 VLM 自己的"思考态度"**。VLM 实际只能填 schema 里的字段，不会说"等一下我先回顾原则 4 再答 Q1"。这一段砍 70%（保留 1-3 + 11 + 16，其余删掉）对输出几乎没有可观察影响。

### 1.4 Drill 知识库（vlm_analyzer.py:519-525） —— 越权污染

让 VLM 推荐 drill。但 drill 推荐在 `diagnosis_engine._get_fix` 里已经由概念图谱直接查表得出，**VLM 输出的 drills 字段实际上被丢弃了**（看 `_generate_narrative` 第 2438-2446，drill 来自 `fix` 不来自 vlm_result）。这段 7 行让 VLM 多生成 200-400 字最终被 throw away。明确删除。

### 1.5 7 个症状群因果链（vlm_analyzer.py:531-645） —— 100+ 行根因诊断逻辑

A-G 七个症状群，每个 15-20 行的多路径排查。**这是引擎层的工作**：诊断引擎用知识图谱做根因追溯（`_trace_root_causes`），VLM 即使按这套链条思考也无法把根因写进 schema（schema 里没有 "深层根因路径" 字段）。

让 VLM 看到这 100 行，会让它在 `overall_assessment` 里硬塞类似 "症状群 C 路径 4：胸肌脱节" 的文字，给 narrative 制造重复诊断，工程量翻倍。

### 1.6 COACH_OUTPUT_PRINCIPLES 黑名单失效

样本 report.md 第 27 行："**核心弹性势能**没建立"——"势能"是 AI 词。第 7 行："第 1 球**暴露**了一个关键问题"——暴露是黑名单类型词。第 116 行："**根因分析**：这些问题的最上游根因是"——这种"X：Y"结构标题正是黑名单第 8 条禁止的。

证据是 COACH_OUTPUT 的黑名单**对 VLM 没拘束力**——因为 VLM 输出的不是最终用户文本，是 JSON。最终给用户的 narrative 是 `_generate_narrative` template-assembled 的，完全绕过 VLM。结果是 prompt 里的"教练讲人话"原则在错的位置——加在 VLM 上没用，应该加在 narrative 生成器上。

### 1.7 重复定义同一概念

"动量交接：躯干在击球瞬间冻结" 在原则 4（vlm_analyzer.py:500）、原则 7（505）、原则 13（513）三次重复。"Out 向量" 在 3、15 重复。"握拍轴心" 在 16 出现，在症状群 G 又重复一次。这种内部冗余约 1500 字。

## 2. 当前 narrative 的问题清单（引用真实输出）

### 2.1 muscle_activation_guide 英文标签泄漏（report.md:26）

> "**muscle_activation_guide preparation**: 腹外斜肌+背阔肌通过离心收缩储能形成的肩髋分离角……"

源头是 `diagnosis_engine.py:2107`，`_CONCEPT_TO_MUSCLE["unit_turn"]["science"]` 字段开头硬写了 "muscle_activation_guide preparation:"。同样的模式在 `prep01_late_split_step` (2141)、`prep04_no_pivot` (2149) 也有。

这是**最严重的一个 bug**：内部 schema 标签被原样拼到给用户的中文叙述里。修复极简单——删掉 `science` 字段开头的 "muscle_activation_guide xxx:" 前缀。

### 2.2 三段式僵化（report.md:22-30）

样本第 1 球的 narrative 是清晰的"段 1 观察 + 段 2 因果 + 段 3 训练"，每段都用同样的模式开头：

> "从视频中观察到以下问题：……量化数据佐证：……"
> "根据知识体系分析，核心问题是「Unit Turn 转开不足」"
> "推荐练习：……做法：……原理：……"

教练讲人话不会用"从视频中观察到以下问题"这种播报员开场。`_generate_narrative` 第 2344 行 hardcode 了 `f"从视频中观察到以下问题：{...}"`，第 2391 行 hardcode 了 `f"根因分析：这些问题的最上游根因是「{root_name}」"`。这些**模板的开头句**就是 AI 腔的源头。

### 2.3 因果链复读自己（report.md:116）

> "根因分析：这些问题的最上游根因是「小臂代偿」。因果链路：「动力链断裂」导致「小臂代偿」。也就是说，你看到的表面症状（A、B）其实是上游问题的下游表现。"

四句话讲一件事。第一句"根因是 X"，第二句"A 导致 X"，第三句"X 是上游"。`_generate_narrative` 第 2391-2395 把图谱原始数据三遍展开。真人教练只会说一遍。

### 2.4 训练历史成为噪音（report.md:28、120）

> "⚠ 训练历史提醒：「小臂代偿 / 手臂主动发力（手臂做独立动作）」在你的训练中出现过 9 次（...2026-03-15、2026-03-26、2026-03-27），已解决。解决方案：4/1 通过腋下贴住（手臂焊在胸上）+ 动力链完整串通解决。最终标志：'完全感受不到胳膊在发力'。核心机制：腋下贴住让手臂变被动，身体转手臂自动跟 |「过度转体（Over-rotation）」在你的训练中出现过 3 次……"

样本第 2 球这段长达 280+ 字，三个历史问题的全文展示。**已解决**的问题被翻出来，**未解决**的问题被淹没。教练不会每次都把训练日志背一遍，只会指出"上次说过的 X 又来了"。

### 2.5 VLM-算法仲裁段落（report.md:113-114） —— 工程师视角

> "🔬 VLM-算法仲裁（共 1 条 VLM 观察被量化数据撤销）：
> V 形 = 现代正手被动 lag drop（非 scooping），已解决"

这是给开发者看的可观测信息，对用户而言纯噪音。emoji 🔬 + "仲裁"这个词都不是教练语言。用户看了只会困惑"为什么内部分歧要让我看到"。

### 2.6 数字播报无解读（report.md:22）

> "（关键数值：同步性 0.71、转体 26°）"

数字在没有上下文时无意义。"同步性 0.71" 是好是坏？阈值在哪？教练应该说"转体只到 26°，标准要 60°，差了一半多"，而不是丢一个裸数字让用户自己理解。

## 3. 重写建议（指导原则 + 关键修改点）

### 3.1 Prompt 层 —— 砍三段、保留一个

**砍掉**（约 6500 字符 → 减半）：

1. 删 L1-L10 整个 Checklist（vlm_analyzer.py:406-422）。schema 已经在结构上约束了，重复 prompting 无收益。
2. 删 L1 击球点专门 block（425-433）。`contact_point` 字段定义已包含同样信息。
3. 删 Drill 知识库（519-525）。VLM 输出的 drill 被丢弃。
4. 把 7 个症状群因果链（531-645）压缩到一个表格："症状 → 优先关注的字段"，30 行内。完整的根因追溯由 `diagnosis_engine` 做，VLM 只需要老实回答 38 个 Q。
5. 16 条原则缩减到 5 条核心原则（保留 1-3 + 11 + 16），且每条不超过 50 字。

**保留并强化**：

逐帧观察 checklist（446-495，图 1-6 的具体观察项）—— 这是真正影响 VLM 输出的部分，因为它直接对应 38 个 Q 的回答。这段不仅不能砍，还应该把每条对齐到具体的 Q 编号。

**移走**：

`COACH_OUTPUT_PRINCIPLES` 从 `_FTT_SYSTEM_PROMPT` 末尾拼接（vlm_analyzer.py:722）的位置**完全删除**。VLM 输出的是 JSON 字段，不是给人读的散文，给它讲"不要用此外、不要三段式"没意义。这段原则应该放在 narrative 生成的 LLM 后处理上（见 3.3）。

### 3.2 Narrative 层 —— 拆掉模板开头句

`_generate_narrative` 三个段落的硬编码开头是 AI 腔的源头：

- 第 2344 行 `f"从视频中观察到以下问题："` → 改成无开场白，直接列问题；或改成动词句 `f"这一拍最大的问题是 X，原因是 Y"`。
- 第 2391 行 `f"根因分析：这些问题的最上游根因是「{root_name}」"` → 删掉"根因分析"这种小标题式开头，直接 `f"根子在{root_name}"`。
- 第 2438 行 `f"推荐练习：{drill}"` → 改成 `f"下一拍只练一个动作：{drill}"`。

把因果链 4 句话压成 1 句（第 2391-2395）：原来 "X 是根因 + A→X + X 是上游 + A 是下游"，改成 "你看到的 A、B，源头都是 X"，一句话。

### 3.3 加 LLM 后处理润色（强烈推荐）

`_generate_narrative` 现在是纯 template-assembled 的字符串拼接，结果就是机械感固化。建议加一道 **后处理 LLM call**（用便宜模型，e.g. Haiku）：

输入：当前组装好的 narrative + COACH_OUTPUT_PRINCIPLES（终于在对的地方用上了）。
任务：单一目标——保留所有事实数据（数字、概念名、drill 名），重写句式让它像教练说话，禁用黑名单词。

这一步成本极低（输入 1500 字、输出 1500 字、一次 call），但能把 AI 腔从源头清掉。比在 VLM 系统 prompt 里加 1453 字的"风格指南"有效得多——因为 VLM 根本不输出散文。

### 3.4 立即可做的 5 个最小修改（不重写）

1. **删 muscle_activation_guide 前缀**（diagnosis_engine.py:2107、2141、2149），3 处共 1 分钟。
2. **删训练历史段**（_generate_narrative:2431-2432）或改成"上次的 X 这次又出现了"一句话，最多 30 字。
3. **删 VLM-算法仲裁可见段**（_generate_narrative:2356-2364）。仲裁结果保留在 `result["arbitration_log"]` 给开发者，但不写进 narrative。
4. **裸数字加阈值**（_generate_narrative:2367-2381）："同步性 0.71（≥0.6 算良好）" 而不是 "同步性 0.71"。
5. **删 prompt 里的 L1-L10 checklist 和 drill 知识库**，约省 4500 字符。

## 4. A/B 对比样例

### 样例 A：第 1 球的开场（report.md:22）

**原版**（93 字，纯 AI 腔）：

> 从视频中观察到以下问题：Unit Turn 转开不足（图 preparation）、在小跳腾空时，球员的视线已经锁定来球方向，但躯干落地后才开始大幅转向。、大臂内侧和胸部侧面有明显空隙（约一个拳头以上），相比准备阶段，间距明显变大。、击球瞬间脊柱与地面接近垂直，没有明显的侧向倾斜。

**修改版**（80 字，教练讲）：

> 这一拍最让我担心的是分裂步落地之后才开始转身——肩只转开 26°，标准要 60°，差了一半多。落地之前那一瞬就该完成预判，落地的那一脚直接就是第一步。

修改要点：删掉"从视频中观察到"播报开场；4 个症状里挑 1 个根因（落地后才转身）讲透；把 "26°" 配上 "标准 60°" 让数字活；删掉"图 preparation"这种字段名泄漏；删掉脊柱、间距等下游症状（它们都是这个根因的结果）。

### 样例 B：第 2 球的因果段（report.md:116）

**原版**（136 字）：

> 根因分析：这些问题的最上游根因是「小臂代偿」。因果链路：「动力链断裂」导致「小臂代偿」。也就是说，你看到的表面症状（准备阶段上半身（肩部和手臂整体）最先开始转动。、是先放到一个位置停顿，然后在前挥时突然下沉拉出的"两步式"动作。）其实是上游问题的下游表现。

**修改版**（48 字）：

> 你感觉是手臂在刷球，其实是动力链先断了——身体转的力没传上来，手臂只能自己代偿。同步性 -0.08，几乎完全独立。

修改要点：删"根因分析"小标题；不重复"小臂代偿"三遍；用"你感觉…其实…"的意图替换句式（COACH_OUTPUT 第 2 条）；把 -0.08 这个关键数字嵌进句中而不是括号里；删掉冗长的"准备阶段……两步式动作"两个 VLM 原文回灌（这些信息在前一段已经说过）。

## 报告

**当前 prompt 最严重的 3 个问题**：(1) 10 层 Checklist + L1 块 + 16 原则 + 7 症状群因果链 ≈ 8000 字「VLM 思考方式指南」，但 VLM 输出的是固定 38-Q schema，全是 dead context；(2) Drill 知识库让 VLM 生成被丢弃的字段；(3) COACH_OUTPUT_PRINCIPLES 加错地方——VLM 不输出散文，给它讲"不要用此外"无效。

**当前 narrative 最严重的 2 个问题**：(1) `muscle_activation_guide preparation:` 英文标签直接漏到中文 narrative（diagnosis_engine.py:2107）；(2) 三个段落 hardcode 开头句"从视频中观察到/根因分析/推荐练习"是 AI 腔固化源头。

**最高优先级的 1 个修改**：在 `_generate_narrative` 后面加一道 LLM 后处理 call（用 Haiku，输入当前 narrative + COACH_OUTPUT_PRINCIPLES，输出重写版）。这是唯一能从根上去掉机械感的改动——template 拼字符串不可能讲人话，必须让 LLM 二次润色。同时把 VLM prompt 里的 COACH_OUTPUT 段删掉（它在那里没用）。
