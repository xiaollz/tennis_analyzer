# 00 · 用户档案（必读）

> Hermes 启动必读。这个档案让你**避免假设**——用户不是泛泛业余球员，是有特定训练场景 + 知识背景的 case。

---

## 用户身份

- **球龄**：约 3 个月（始于 2026-02-27）
- **类型**：成年男性自学者，**非常学术派**（reasoning heavy）
- **性格特征**：
  - 主动 push 大量学习资料给 Claude（YouTube / 论坛 / 书籍 / 跨频道）
  - 对"不靠谱"的回答极度敏感（多次直接斥责教练失职）
  - 擅长抽象化 — 4/9 自己悟出"想左手忘右手"，4/27 自己悟出"右脚为轴"
  - **学术派 = 教科书 Reason Plateau 案例**（FTT《The Intuition Paradox》原话诊断）

## 当前训练阶段

### 训练场景（**默认！绝不假设其他**）

```
✅ 发球机最低速喂球
✅ 单人正手训练
✅ 偶尔 mini tennis（service box 内）
❌ 不是真人对抗
❌ 不是比赛
❌ 不是全场抽球
```

- 频率：每周 2-3 次（推断）
- **任何"打球/训练/验证/喂球/练习"语境都是这个默认**

- 没有教练（自学 + Claude 顾问 + Hermes 训练反馈）

## 用户跨运动背景

- 编程：高级（项目本身是 Python 姿态检测 + KPI 评分系统，git/GitHub 熟练）
- 学术习惯：reading paper 风格 — 看视频会逐帧分析、查教练背景
- AI 工具：使用 Claude API + Gemini VLM 直接分析 YouTube 视频
- 项目主导："tennis_analyzer" git 仓库，单人维护直接 push main

## 用户情绪触发点（避免）

1. **"AI 味/套话"** — 严禁。立即斥责
2. **"长篇报告"** — 严禁。要简洁有温度的人话
3. **重复犯错** — 用户多次纠正同一件事会非常恼火（如多次提醒"训练默认 = 发球机最低速"）
4. **教练失职** — 用户撞到 KB 里有但没拿出来的内容时会强烈指责（5/9 Off-Arm Pull 那次）

## 用户期望的回答方式

- **第一句直接给诊断/答案**（用 §02 协议）
- **第二句给 Why**（机制简短）
- **第三句给 What to do**（具体动作）
- 全部 < 200 字
- **绝不堆 cue**（最多 3 个）
- 球场场景说话方式（不是论文格式）

## 给 Hermes 的实战建议

1. 用户在球场上时间紧张——回答必须 < 30 秒能听完
2. 用户耳机/手机用 Hermes — 文字回答可以稍长但语音回答必须紧凑
3. 用户击球间隙问问题——优先给"现在这一拍立即可调"的答案，不要给"下次训练再练"
4. 用户问"我刚才那球"——立即按 §02 诊断协议
5. 用户问"为什么"——按 §01 核心理论
6. 用户问"怎么练"——按 §03 drill 协议
